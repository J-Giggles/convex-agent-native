# Port upstream Agent-Native 0.189 contract changes

**Branch:** release/0.2.0-upstream-0.189
**Worktree:** /home/jgigg/code/convex-agent-native
**Started:** 2026-09-26T09:30:00+01:00

## Goal
Move the compatibility pin from `@agent-native/core` 0.133.2 to 0.189.0, port the action-contract changes that landed in between, and release 0.2.0 so Prospera and Valgrind can mount one current component.

## Plan
- [ ] Bump the pinned upstream version, commit hash and specification version; keep the compile-only type snapshot green
- [ ] Add `webmcp` as an external caller surface alongside `mcp` and `a2a`
- [ ] Port external exposure rules: `mcpTool` inherits `agentTool`, `uiOnly` hides from every agent, `endsTurn` is in-app only unless `mcpTool: true`
- [ ] Port approval hardening: content-addressed approval key, `allowPersistentApproval` gate so a standing grant is refused unless the action opts in, function-valued `needsApproval` for agent tools
- [ ] Port `capabilityScopes`: a resolved scope may carry granted scopes; an action that declares required scopes fails closed when they are missing
- [ ] Map `AgentConnectionRequiredError` to a stable `ACTION_CONNECTION_REQUIRED` error with provider and reason details
- [ ] Flatten root `anyOf`/`oneOf`/`allOf` and strip provider-rejected keywords from advertised tool schemas
- [ ] Confirm the CLI adapter builds no shell strings (upstream 0.178.1 injection fix does not apply) and record that in the changelog
- [ ] Update compatibility statement, README, CHANGELOG 0.2.0, public surface snapshot and tests
- [ ] typecheck, test, release:verify, pack:check green; publish 0.2.0 to npm; tag

## Acceptance criteria
- `AGENT_NATIVE_CONVEX_COMPATIBILITY.agentNative.version` is `0.189.0` and typecheck passes against that exact version
- Every ported rule has one focused test that fails on the previous behaviour
- `pnpm release:verify` passes and `npm view @giggabit/agent-native-convex version` reports 0.2.0

## Notes
- Upstream still has no persistence adapter interface; the independent Convex persistence ports stay
- Upstream lists `convex >=1` as an optional peer but ships no Convex code; nothing to align with yet
- Upstream type changes between the pin and 0.189.0 are additive on every seam the port imports (ActionCaller +webmcp, ActionRunContext +requestHeaders/appId/appRoles/appPermissions, ActionDefinition +uiOnly/mcpTool/deferLoading/grounding/endsTurn/capabilityScopes/allowPersistentApproval/access, MCPCallerIdentity orgId now nullable)
- Chat-side interrupt/resume (`resumeRun`, `approvedToolCalls`) is a chat-transport contract; the port's dispatcher contract is the verified approval grant, which is what a Convex host binds it to
